# App compatibility work notes

These sanitized notes prevent agents from repeating completed compatibility
research. Read the target app's note before running it. Update the note on its
`compat/<app-slug>` branch when a proven fact, rejected hypothesis, repeatable
input route, or next discriminator changes.

A work note is not a compatibility database report. It may describe provisional
or dirty-worktree experiments as long as they are clearly labeled. Only
`compatibility/apps/*.json` records results reproduced with an exact
hash-verified artifact on a committed tapHLE revision.

Follow the template and content restrictions in
`dev-docs/app-debugging-playbook.md`. In particular, never include proprietary
code or data, extracted assets, screenshots, raw logs, keys, or personal paths.
